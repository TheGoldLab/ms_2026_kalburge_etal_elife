# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Analysis code for "Human decision-makers terminate evidence accumulation using flexible decision rules" (Kalburge, Dallstream, Josić, Kilpatrick, Ding, Gold). This is a research codebase, not a library or app: `pigeon/` is a small, stable data-processing/simulation package, and `notebooks/` contains the actual analyses that reproduce every figure and table in the paper. Most of `pigeon/` is a Python translation of an existing MATLAB pipeline (`getPigeon_*.m` functions) — when in doubt about intended behavior, the MATLAB origin is the source of truth, and docstrings note which `.m` file a function was translated from.

## Setup and commands

- Install: `uv sync` (or `pip install -e .`), Python ≥ 3.13.
- Before anything else works, edit [pigeon/pathDefaults.py](pigeon/pathDefaults.py) to point `RAW_DATA_DIR`, `DATA_DIR`, and `FIGURES_DIR` at real locations on disk — these are machine-specific and not portable.
- There is no test suite, linter, or build step (no pytest/ruff config in `pyproject.toml`). Correctness is checked by running notebooks and comparing outputs against the MATLAB pipeline / expected figures — see "Tests and diagnostics" notebooks below.
- Run notebooks via Jupyter (`jupyter` is a listed dependency): `jupyter lab` / `jupyter notebook`, or execute in-place with `jupyter execute notebooks/<name>.ipynb`.

### Notebook run order matters

1. `notebooks/Make_biasCorrection.ipynb` → generates `boundBiasCorrection.mat` (or the newer `boundSummary`/`simBounds` interpolation table). Required before any bound analysis, since `get_data_table` applies bias correction by default.
2. `notebooks/Make_RRMatrix.ipynb` → generates `RRMats.mat`, consumed by `Figure04_RRvsBound` and `Figure06_cpSummary`.
3. Figure/Table notebooks can then be run in any order.

The CP (change-point) task is **not implemented in Python** — `Figure06_cpSummary` and `Make_RRMatrix` consume a pre-computed `boundSummaries_wCP.mat` produced by the separate MATLAB pipeline.

## Architecture

### Data flow

Raw per-subject CSVs (`Pigeon_OL/`, `Pigeon_MX/`, `Pigeon_PD/` under `RAW_DATA_DIR`) → [pigeon/data.py](pigeon/data.py) `get_data_table()` → a per-trial DataFrame → [pigeon/stats.py](pigeon/stats.py) summary functions and the figure notebooks. [pigeon/simulate.py](pigeon/simulate.py) produces synthetic data tables in the *same* DataFrame schema so simulated and real data can be dropped into the same downstream code interchangeably.

Everything downstream keys off two things computed once, early, in `get_data_table`:
- **bound** — the accumulator position at decision-threshold crossing, inferred from the raw step sequence by `get_bounds()`, not measured directly. This is the central derived quantity of the whole project.
- **quality/reliability flags** (`wall_hit`, `rt_below_cutoff`) — every analysis is expected to filter through `get_good_trial_array()` rather than re-deriving its own filter logic.

### The bound-inference algorithm (`get_bounds` in data.py)

This is the trickiest piece of logic in the codebase and most bugs/edge cases live here:
1. Build a "bound matrix": for each trial, midpoints between consecutive step positions at each possible NDT (non-decision-time) lag before the response.
2. Pick an NDT lag per SNR group — either fixed (`ndt=<int>`) or the lag that maximizes *congruence* (agreement between the sign of the midpoint bound and the actual choice direction).
3. Extract the bound at that lag, with an optional "peak-step" correction (`peak_step_bound=True`) for trials where the pigeon is moving back toward center at the crossing — this avoids underestimating the bound.
4. Compute a per-(block, SNR) RT reliability cutoff: the minimum RT at which congruence is high enough to trust the bound estimate (`_compute_rt_cutoff`).

`get_bounds_from_dv` is a vectorized sibling used when a full DV matrix is already available (e.g. simulation output), rather than per-trial ragged step arrays.

### Bias correction

Real and simulated bounds are systematically biased (nonlinear near zero). `apply_bias_corrections()` corrects for this using a calibration table generated by `Make_biasCorrection.ipynb` and stored as a `.mat` file at `BIAS_CORRECTION_FILE`. It prefers interpolation (`boundSummary`/`simBounds` — inverts the measured→true bound curve via `np.interp`) and falls back to legacy per-(DT bin, SNR bin) linear coefficients (`boundBiasCorrection`) for older calibration files. `get_data_table` and `get_simulated_data_table` both apply this by default (`correct_bias=BIAS_CORRECTION_FILE`); pass `correct_bias=None` to get raw uncorrected bounds.

### Simulation (`pigeon/simulate.py`)

`simulate_trials()` is the core generative model: a vectorized random-walk accumulator with an absorbing bound, configurable NDT distribution (fixed, uniform, Gaussian-weighted, or bound-dependent), optional lapse rate, and optional sensory noise (subject decides on a *perceived* DV, but returned step sequences are the *true* DV, matching what `get_bounds` would infer from real screen data).

`get_simulated_data_table()` wraps this to produce a full data table matching `get_data_table`'s schema, in two modes:
- **data_table mode**: infers per-subject/block generative parameters (drift, NDT, bound) from a real data table according to `bound_type` (`'given'`, `'fixed'`, `'true'`, `'var'`) — used to generate matched simulations for comparison against real subjects.
- **specs mode**: fully parametric, all simulated subjects share the same parameters — used for exploring the model's predictions independent of any real subject.

Important distinction: for bias-correction calibration itself, call `simulate_trials` directly with `num_trials=1_000_000`, *not* `get_simulated_data_table`, since the latter truncates each simulated block to a ~600-step budget (`BLOCK_DEFAULTS`) to match real experimental sessions.

### Adaptation fits (`pigeon/adaptation.py`)

Fits within-block adaptation time constants (tau) to smoothed, z-scored |bound| trajectories, with a permutation-based significance pipeline (per-subject test against shuffled-order nulls, plus a max-stat corrected group null band) that gates which subjects/blocks get a tau fit at all. This exists so `Figure04_RRvsBound` (tau insets) and `Figure03S04_sequentialAnalysis` fit tau the same way, from the same eligibility criteria, on the same data — don't reimplement tau-fitting logic elsewhere; call `get_adaptation_tau_fits()`.

### Notebooks

`notebooks/` is organized as preprocessing (`Make_*`) → main figures (`FigureNN_*`) → supplementary figures (`FigureNNSNN_*`) → tables (`Table_*`) → tests/diagnostics (`Test_*`). The `Test_*` notebooks (`Test_NDT`, `Test_boundDefinition`, `Test_cpData`, `Test_trialQuality`) are the closest thing this project has to a test suite — validating the bound-inference algorithm, NDT consistency, and trial-quality filtering — and are the right place to check when modifying `pigeon/data.py` core logic. See the notebook index and full module/function table in [README.md](README.md) for what each one produces.

### Plotting

[pigeon/plotting.py](pigeon/plotting.py) is minimal — `FONT_RC` (embeds real font outlines in saved PDF/EPS so text stays editable in Illustrator) and `add_panel_label()` for figure panel letters. Figure notebooks import these rather than each redefining font/panel-label styling.

## Style conventions

**Naming**
- Functions: snake_case, verb-first (`get_data_table`, `apply_bias_corrections`, `fit_exp_tau`). Module-private helpers get a leading underscore (`_compute_rt_cutoff`, `_build_window_matrix`).
- Constants: UPPER_SNAKE_CASE (`WALL`, `MIN_BOUND`, `BLOCK_DEFAULTS`, the path constants in `pathDefaults.py`).
- Boolean mask variables carry a MATLAB-inherited `l`-prefix instead of `is_`/`has_` names: `lg` (good-trial mask), and short combinable masks like `ls`, `lsb`, `lsnr`, `lrt`, `lc` that get ANDed together (`lg & ls & lsnr`) as filters narrow. Follow this pattern rather than introducing `is_valid`/`mask_x` names when editing `data.py`, `stats.py`, or `adaptation.py`.
- Loop indices pair an abbreviation with its source collection: `si`/`subj` (subject), `bi`/`block`, `ni` or `mm` (SNR), `ri` (RT/DT bin), `dd` (DT bin), `ii`/`tt` (trial).
- Domain abbreviations (`DT`, `RT`, `NDT`, `SNR`, `DV`) stay uppercase in DataFrame column names (`data_table["DT"]`, `data_table["RT"]`) but lowercase in local variables/params (`dts`, `rts`, `ndts`, `min_dt`) — match whichever context you're in, don't normalize one to the other.
- `abs_` prefix marks the absolute-value variant of an existing name (`bound` → `abs_bound`, `snr` → `abs_snr`, `DV` → `abs_DV`) rather than a differently-named variable.
- Distribution/range parameters use `_mean`/`_std` and `_min`/`_max` suffixes (`generative_mean`, `bound_std`, `ndt_min`), even for one-off simulation knobs.
- `data_table` is the conventional first-positional-arg name for any function consuming the standard trial-level schema (`stats.py`, `adaptation.py`) — keep using it rather than `df`.

**Randomness**
- Stochastic functions (`simulate_trials`, `get_simulated_data_table`, `compute_per_subject_curves_with_nulls`) take `rng=None` and default internally to `np.random.default_rng()` (or a fixed `seed` for permutation tests). Thread a caller-supplied `Generator` through rather than calling `np.random` module-level functions, so callers can control reproducibility.

**Docstrings**
- NumPy-style (`Parameters`/`Returns` sections with dashed underlines) on every public function.
- When a function is a direct port of MATLAB code, note the source file in the first lines (`Translated from getPigeon_bounds.m`) — keep doing this for anything still being ported.
- Module docstrings describe the pipeline/algorithm in enough detail to avoid reading the whole file (see the tops of `data.py`, `simulate.py`), not just a one-line summary.

**Comments**
- Inline comments justify *why*, especially non-obvious math or a MATLAB-compatibility constraint (e.g. `simulate.py`'s NDT draw citing the exact MATLAB `randi` expression it reproduces). Don't add comments that restate the code.

**Notebooks**
- Filename pattern: `<Category><NN>[S<NN>]_<camelCaseDescription>.ipynb`. Categories: `Make_` (preprocessing), `Figure` (main figure), `FigureNNSNN_` (supplement, numbered under its parent figure), `Table_`, `Test_`. Number to match the paper.
- New analysis notebooks should call into `pigeon` rather than reimplementing bound inference, trial filtering, or summary stats inline — that duplication is exactly what the package exists to prevent.

**Vectorization**
- Prefer vectorized NumPy over per-trial Python loops for anything running at simulation scale (see `simulate_trials`'s crossing detection, explicitly commented "fully vectorized, no Python step loop"). The per-trial loops in `get_bounds` (`data.py`) are a deliberate exception kept for clarity/parity with the MATLAB original — don't assume they need vectorizing too.
